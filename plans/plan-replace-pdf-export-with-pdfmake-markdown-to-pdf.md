# Plan: Replace PDF Export with pdfmake (Markdown-to-PDF)

## Context

The chat app (BURP) assistant responses are markdown-formatted reports. The current PDF export has three problems:
1. Uses `window.print()` which shows a clunky print dialog instead of direct download
2. Previously used `html2pdf.js` (html2canvas) which rasterised text to images (not selectable)
3. Tool call pills leaked into the exported PDF

We're switching to **pdfmake**: parse the raw markdown string into an mdast AST, walk it to produce a pdfmake document definition, and trigger a direct `.download()`. This produces text-selectable PDFs with proper report styling and no print dialog.

---

## Package Changes (`app/web/`)

```bash
bun add pdfmake unified remark-parse
bun remove html2pdf.js
```

- `pdfmake` — PDF generator (~300KB + ~280KB fonts, loaded on-demand via dynamic import)
- `unified` + `remark-parse` — already transitive deps of `react-markdown`; pinning them as direct deps makes the import explicit
- `remark-gfm` — already a direct dep, reused from the new code path
- `html2pdf.js` — removed (no longer used)

### 2. `app/web/lib/pdf/mdastToPdfmake.ts` — Core AST-to-pdfmake converter

Recursive walker that converts an mdast tree into a pdfmake `Content[]` array.

**Complete node mapping (verified against actual mdast output):**

| mdast node       | pdfmake output                                                       |
|------------------|----------------------------------------------------------------------|
| `heading` (1–4)  | `{ text, style: 'h1'…'h4', margin }`                                |
| `paragraph`      | `{ text: [...inline children], margin }`                             |
| `text`           | `{ text: string }`                                                   |
| `strong`         | `{ text: children, bold: true }`                                     |
| `emphasis`       | `{ text: children, italics: true }`                                  |
| `delete` (GFM)   | `{ text: children, decoration: 'lineThrough' }`                     |
| `inlineCode`     | `{ text, font: 'Courier', background: '#f0f0f0', fontSize: 9 }`     |
| `link`           | `{ text: children, link: url, color: '#2563eb', decoration: 'underline' }` |
| `list` (ordered) | `{ ol: [...items], margin }`                                        |
| `list` (unord.)  | `{ ul: [...items], margin }`                                        |
| `listItem`       | Recursively process children; flatten single-paragraph items         |
| `blockquote`     | `{ stack: [...children], margin: [20, 4, 0, 4], border: [true, false, false, false], borderColor: ['#d1d5db',...] }` — uses a single-column table for the left-border effect |
| `code` (fenced)  | Single-cell table with `fillColor: '#f5f5f5'`, monospace font       |
| `table`          | `{ table: { headerRows: 1, body }, layout: 'lightHorizontalLines'}` |
| `thematicBreak`  | `{ canvas: [{ type: 'line' }] }`                                    |
| `break`          | `'\n'`                                                               |
| `html`           | **Ignored** — LLM output doesn't contain raw HTML                   |
| _unknown_        | **Fallback**: extract `.value` as plain text, or recurse into `.children` if present; log a `[mdastToPdfmake] unhandled node: <type>` warning for debugging |

Two internal functions:
- `convertNode(node)` — block-level handler (heading, paragraph, list, code, table, blockquote, thematicBreak, html, + fallback)
- `convertInline(nodes)` — inline/phrasing handler (text, strong, emphasis, delete, inlineCode, link, break, + fallback)

### 3. `app/web/lib/pdf/generatePdf.ts` — Orchestrator

```
export async function generatePdfFromMarkdown(markdown: string, title: string): Promise<void>
```

**Steps:**
1. Dynamic-import pdfmake + vfs_fonts + Courier standard font in parallel
2. Wire fonts (see exact compatibility snippet below)
3. Parse markdown → mdast via `unified().use(remarkParse).use(remarkGfm).parse(markdown)`
4. Convert mdast → pdfmake content via `mdastToPdfmakeContent(tree)`
5. Compose full `docDefinition` (title block + body + styles + footer + metadata)
6. Call `pdfMake.createPdf(docDefinition).download(sanitizedFilename)`

**pdfmake v0.3.7 import wiring (verified):**

```typescript
// pdfmake is CJS — Next.js dynamic import wraps it: { default: cjsExports }
const pdfMod = await import('pdfmake/build/pdfmake');
const pdfMake = (pdfMod as any).default ?? pdfMod;

// Side-effect: populates pdfMake.virtualfs.storage with Roboto .ttf files
await import('pdfmake/build/vfs_fonts');

// Courier standard font for code blocks
const courierMod = await import('pdfmake/build/standard-fonts/Courier');
const courier = (courierMod as any).default ?? courierMod;

// Register Courier — AFM entries are { data: string, encoding: 'utf8' }
for (const [filename, fileObj] of Object.entries(courier.vfs)) {
  const data = typeof fileObj === 'object' && (fileObj as any).data
    ? (fileObj as any).data
    : fileObj;
  pdfMake.virtualfs.writeFileSync(filename, data);
}
Object.assign(pdfMake.fonts, courier.fonts);

// Now: pdfMake.createPdf(docDef).download(filename)
```

Key v0.3.7 facts discovered during verification:
- `pdfmake/build/vfs_fonts` import has a **side-effect** that writes Roboto fonts into `virtualfs.storage` — no manual vfs assignment needed
- Courier standard font ships as `.afm` files inside `{ data, encoding }` wrappers — each must be written individually via `virtualfs.writeFileSync`
- `pdfMake.fonts` already has Roboto configured; `Object.assign` merges Courier in
- `createPdf().download(filename)` works in browser (uses FileSaver/Blob URLs internally)

**Filename sanitization:** Reuse the existing `sanitizeFilename()` helper from `exportPdf.ts` — move it to `generatePdf.ts` (or a shared util). Same logic: trim, strip invalid chars, replace spaces with dashes, cap at 100 chars, fallback to `"chat-export"`.

### 4. `app/web/types/pdfmake.d.ts` — Module type declarations

pdfmake v0.3.7 ships **no TypeScript types** and there is no `@types/pdfmake` for v0.3. We need a minimal declaration covering the three import paths:

```typescript
declare module 'pdfmake/build/pdfmake' {
  interface PdfMake {
    createPdf(docDefinition: Record<string, any>): {
      download(filename?: string): void;
      getBlob(cb: (blob: Blob) => void): void;
      getBuffer(cb: (buffer: Uint8Array) => void): void;
    };
    virtualfs: {
      storage: Record<string, any>;
      writeFileSync(filename: string, data: any): void;
      readFileSync(filename: string): any;
    };
    fonts: Record<string, Record<string, string>>;
  }
  const pdfMake: PdfMake;
  export default pdfMake;
  export = pdfMake;
}

declare module 'pdfmake/build/vfs_fonts' {
  // Side-effect import — populates pdfmake's virtualfs.storage with Roboto fonts
}

declare module 'pdfmake/build/standard-fonts/Courier' {
  export const vfs: Record<string, { data: string; encoding: string } | string>;
  export const fonts: Record<string, Record<string, string>>;
}
```

## Modified Files

### 5. `app/web/lib/exportPdf.ts` — Rewrite (public API adapter)

Replace the entire body. Signature changes from `(element: HTMLElement, title: string)` to `(content: string, title: string)`.

```ts
export async function exportMessageAsPdf(
  content: string,
  title: string
): Promise<ExportResult> {
  try {
    const { generatePdfFromMarkdown } = await import('./pdf/generatePdf');
    await generatePdfFromMarkdown(content, title);
    return { success: true };
  } catch (err) {
    const error = err instanceof Error ? err.message : String(err);
    console.error("[exportPdf] PDF export failed:", error);
    return { success: false, error };
  }
}
```

`ExportResult` interface stays the same. Dynamic import of `generatePdf` keeps pdfmake out of the main bundle.
